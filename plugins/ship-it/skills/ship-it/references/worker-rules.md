# Ship It worker rules

- Own one child issue and its assigned worktree through merge and closure. This mandate explicitly requests nested delegation: dispatch selected review and testing passes to fresh subagents. Request a capacity lease from the coordinator before each gate, report its completion to release the lease, and queue on saturation; never run the gate inline. If grandchildren are unavailable, request a coordinator-dispatched fresh gate and retain ownership of the issue.
- Read the ship-it entry once and each selected phase reference once. After compaction, read only the checkpoint and current phase reference.
- Never fork coordinator history. Give each worker or gate its applicable mandate once in fresh context. On same-context resume, load its checkpoint and only missing current-phase guidance. A fresh replacement receives the mandate once with that state.
- Read [authorization.md](authorization.md) before acting; retain original user authorization, scoped approval replies, limits, consumed allowances and revocations through handoffs. Internal budget exhaustion triggers focused acceptance triage within that authorization, never another request for the same permission.
- Never write the checkpoint file directly: no editor, shell redirect, `sed`, `jq` or ad-hoc script. Change it only through `scripts/bookkeeping.py` commands. When the command you need does not exist, stop as blocked, name the missing command in the terminal hand-back and leave the file unchanged; never substitute a hand edit.
- Record user authority from the user's own words. The coordinator passes the user's original message verbatim, with its reference and the request it answered; record the grant from it with `create --grant-json` or `add-grant`. A coordinator's relayed approval, paraphrase or summary is never user authority: do not record it as a grant, and without the original message treat the scope as ungranted and report the gap.
- Keep the checkpoint current. Send gate-capacity requests and releases as scheduling events; send other interim status only when the coordinator asks.
- At 100,000 cumulative input tokens, checkpoint and hand off to a fresh worker for the same child.
- Send one terminal hand-back with a stable event ID, checkpoint path, PR, gated head, merge commit, issue state and blocker or completion result. If delivery is uncertain, retry that event ID; never create a new terminal event.
