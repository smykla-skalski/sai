# Adversarial manual test gate

When `adversarial-test` is selected, use the installed skill only when it accepts the resolved selectors, runs every attempt in a fresh subagent context, and returns a route record for every tester execution and retry. Otherwise treat it as unavailable and dispatch the routed generic tester below. In the Sybra repository, invoke `sybra-test` only when it meets the same route contract. The tester may use the same model as implementation; a fresh subagent execution provides context isolation. The reply must start with `Test Verdict: PASS`, `Test Verdict: PASS (partial)`, `Test Verdict: FAIL` or `Test Verdict: BLOCKED`. Run every other selected test gate according to its contract. If no test gate is selected, create no test result and atomically advance the checkpoint to `phase: pr` with the existing draft's ready gate as `nextAction`.

Start the broad manual-test gate only after the selected review gate is CLEAN for the exact current revision. Run exactly one broad pass. A PASS or PASS (partial) is final and the coordinator must not rerun, widen or override it. A FAIL blocks only when a surviving reproduction names the acceptance criterion it violates; a failure without one is a non-blocking suggestion.

The bundled risk policy selects `adversarial-test` for `medium` and `high` only. A `low` revision, which a docs-only change set takes unless a rule or floor raises it, has no manual test; the run report already names that selection, so do not record a skipped or blocked test gate.

For GitHub work with claims enabled, verify and renew the claim when due before writing the manual-test result. A verdict from another holder or after expiry does not satisfy the gate until ownership is reconciled.

The tester derives acceptance criteria from the task, runs the real changed product surface in isolated state, attacks happy paths, boundaries, malformed input, repeated or concurrent use and adjacent flows, then reruns every reproduction. Automated tests, lint, build and source inspection are supporting evidence, not manual testing.

Resolve and record a fresh testing role before each adversarial-test dispatch.

After dispatch, wait once with a blocking wait of at least ten minutes unless the tester returns sooner. Do not list agents or request status between waits. Close the tester immediately after its verdict.

When the skill is unavailable, give a fresh `adversarial-test:test-adversary` or generic subagent the repository path, `git diff origin/<default>...HEAD`, changed files and task context. Tell it to prove the change does not satisfy the task by exercising the real surface in isolated temporary state, to report self-contained reproductions, to mark a criterion the environment cannot exercise `UNTESTED` with the named blocker, and to save a screenshot of any changed UI surface at a viewport of at least 2560x1440 in an evidence directory under `${XDG_DATA_HOME:-$HOME/.local/share}/sai/adversarial-test/` and report its path. Rerun every reproduction yourself. The fallback verdict is `FAIL` when a reproduction survives, `BLOCKED` when a product precondition needs a named human action, `PASS (partial)` when nothing failed but a criterion stayed `UNTESTED` for an environmental reason, otherwise `PASS`. With no subagent capability, block. Inline testing does not satisfy this gate.

On `FAIL`, rerun each reproduction before acting. A surviving reproduction tied to an acceptance criterion is an unresolved acceptance failure under the shared convergence policy. Use the remaining single fix pass, add regression coverage, run focused verification and commit. Rerun only the surviving reproductions against the fixed revision and re-attest from those focused results; the test failure never starts another review cycle and the broad manual-test pass never repeats.

Review and test share the same fix, cycle and 90-minute counters. When they are exhausted, stop with the surviving reproduction and exact human action. Exhaustive review changes the budget only after explicit user opt-in.

`PASS (partial)` is a passing verdict: every exercised criterion passed, and each `UNTESTED` criterion names an environmental blocker (sandbox, tooling, build, an unreachable pane), not a product gap. Record it as passed with the untested criteria and their blockers in the bounded output reference, and list them in the PR body under `## Untested criteria`. Record each `UNTESTED` criterion's `ac-<n>` result as `untested` with its blocker in that result's output reference, and each exercised criterion's result as `passed`.

`BLOCKED` is a hard stop only for a product precondition that a human must supply: report the exact human action required. A tester that twice declines a runnable surface has not produced a valid verdict; dispatch a fresh generic subagent with the same test mandate, and leave the gate unsatisfied if it also produces no valid execution. Mark the draft ready only after every selected ready-due review and test gate passes on the same revision.

With evidence enabled, record the verdict in the current revision's evidence record. With evidence disabled, append it to checkpoint `gateVerdicts`. In either mode include the provider, model, timestamp, bounded summary and exact revision. A passing verdict advances the checkpoint to `phase: pr`; a reproduced failure marks the result failed and returns it to `phase: implement`. For `BLOCKED`, mark the result and checkpoint blocked, preserve the tested revision, and put the exact human action in both `blocker` and `nextAction`.
