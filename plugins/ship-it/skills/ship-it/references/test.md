# Adversarial manual test gate

Use the installed test skill (or `sybra-test` in Sybra) only if it honors selectors, fresh contexts per attempt and a route record for every tester execution and retry; otherwise use a generic tester. The tester may use the same model as implementation. Match verdicts as whole lines, so `Test Verdict: FAILED` is never read as `Test Verdict: FAIL`. Accept `Test Verdict: PASS`, `Test Verdict: PASS (partial)`, `Test Verdict: FAIL` or `Test Verdict: BLOCKED`. `Test Verdict: FAILED` (unresolved base ref), or a git error on `git diff origin/<default>...HEAD` in a generic path, is a failed gate, never a pass: record a failed result (evidence, or `gateVerdicts` without evidence), set `status: blocked` with its `Gate failure:` line as `blocker`, and start no fix pass. `nextAction` is to fetch the base ref for an unresolved ref or git error, else to rerun the gate. A `PASS` whose second line starts `No test performed:` examined nothing: record no pass and leave the gate unsatisfied until it is rerun or the diff proves empty. Run every selected test gate. With none selected, record no result and advance to the existing draft's ready gate.

Start testing only after the selected review gate is CLEAN for the exact current revision. Run exactly one broad pass. Assess the manifest and reserve `test` with `bookkeeping.py reserve --inputs-json MANIFEST`; dispatch only on `dispatch: true`, then finish. Reuse verified results with current-head provenance. PASS or PASS (partial) is final: the coordinator must not rerun, widen or override it. FAIL blocks only when a surviving reproduction names the violated criterion; otherwise it is a non-blocking suggestion.

Bundled policy selects `adversarial-test` for `medium` and `high` only. Low risk selects no manual test: record no skipped or blocked result.

For `small-code`, read [risk.md](risk.md) for the `testScope: changed-surface` mandate. Ordinary code profiles retain the broad mandate.

For GitHub work with claims enabled, verify and renew the claim when due before writing the manual-test result. A verdict from another holder or after expiry does not satisfy the gate until ownership is reconciled.

The tester derives acceptance criteria from the task, runs the real changed product surface in isolated state, and attacks happy paths, boundaries, malformed input, repeated or concurrent use and adjacent flows. Every reproduction rerun is a separate attempt: dispatch it to a fresh subagent execution, including checks before a fix and focused checks after a fix. Automated tests, lint, build and source inspection are supporting evidence, not manual testing.

Resolve and record a fresh testing role and stable dispatch ID before each adversarial-test dispatch. Apply [worker-events.md](worker-events.md).

For a generic tester, supply repository, `git diff origin/<default>...HEAD`, changed files and checkpoint. Exercise the isolated real surface; report reproductions and `UNTESTED` environmental blockers. For changed UI, save a screenshot of at least 2560x1440 under the persistent adversarial-test evidence directory. Dispatch every reproduction rerun to a fresh subagent execution. A surviving reproduction is `FAIL`; a human-supplied product precondition is `BLOCKED`; only environmental gaps yield `PASS (partial)`; otherwise `PASS`. With no subagent capability, block; Inline testing does not satisfy this gate.

On `FAIL`, dispatch each reproduction check before acting to a fresh subagent execution. A surviving reproduction tied to an acceptance criterion is an unresolved acceptance failure under the shared convergence policy. Use the remaining single fix pass, add regression coverage, run focused verification and commit. Rerun only the surviving reproductions against the fixed revision in fresh subagent executions and re-attest from those focused results; the test failure never starts another review cycle and the broad manual-test pass never repeats.

Review and test share the same fix, cycle and 90-minute counters. When they are exhausted, triage the surviving reproduction under [authorization.md](authorization.md): perform focused acceptance recovery inside active authorization and explicit user limits, defer optional findings, and stop only for an unresolved blocker.

`PASS (partial)` is a passing verdict: every exercised criterion passed, and each `UNTESTED` criterion names an environmental blocker (sandbox, tooling, build, an unreachable pane), not a product gap. Record it as passed with the untested criteria and their blockers in the bounded output reference, and list them in the PR body under `## Untested criteria`. Record each `ac-<n>` result as `untested` (blocker in its output reference) or `passed`.

`BLOCKED` is a hard stop only for a product precondition that a human must supply: report the exact human action required. A tester that twice declines a runnable surface has not produced a valid verdict; dispatch a fresh generic subagent with the same test mandate, and leave the gate unsatisfied if it also produces no valid execution. Mark the draft ready only after every selected ready-due review and test gate passes on the same revision.

Record provider, model, timestamp, bounded summary and exact revision in enabled evidence or checkpoint `gateVerdicts`. Passing verdicts advance to PR; a reproduced failure marks the result failed and returns to implement. BLOCKED preserves the tested revision and records the required human action in the result, workflow blocker and next action.
